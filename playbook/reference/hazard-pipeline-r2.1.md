## Why this matters to the notebook
The `ensemble_season_timeseries` and `*_trends*` parquet under
`domain=climate/.../processing=timeseries_mean_month/` are this script's outputs.
When the notebook throws `Binder Error: column "iso3" not found` or
`TProtocolException: Invalid data`, or Future Projections cold-fetch is slow, the
cause is usually producer-side here.

## CR-119 — `iso3` dropped from canonical (root cause + fix)
2026-06-05 publish broke every reader: `iso3` missing from schema, files ~14× too big,
aggregate scans threw thrift errors.
- **iso3 dropped** — §3.3 *and* §3.4 aggregation `by=` clauses omitted `iso3`;
  `write_parquet_pushdown` silently drops absent sort columns. Fixed in §3.3
  (`b83dd3f`) and §3.4 (`9117450`). **All `*_trends*.parquet` must be regenerated.**
- **14× size** — `models` GCM list was a per-row string; now JSON-sidecar only.
- **thrift corruption** — parallel §3.3 writers collided on a shared path; §3.3 is now
  sequential.
- **Acute fix used:** S3 object-versioning rollback to the prior canonical (bucket is
  versioned) — see `ISSUE_cr119_canonical_regression.md` for the exact `aws s3api` steps.

## §3.4 trend speedup (~9 h/timeframe → minutes)
Single-pass Rcpp Theil–Sen + Mann–Kendall kernel (`R/trend_kernel.cpp`) + baseline-fit
dedup + ts0 reuse. ~63× per fit, numerically identical to `trend::` (validated). Gated
by `USE_TREND_KERNEL`, falls back to `trend::` if it can't compile.

## ⚠️ Known bug — multisession §3.4 broken with the kernel
`future_lapply` over source groups `FutureInterrupt`s immediately when the kernel is on
(suspect: concurrent per-worker `Rcpp::sourceCpp` racing the shared cache). **Workaround:
run with `R21_SEC3_4_SEQUENTIAL=1`** (forces `plan(sequential)`; ~1.5–2.5 h for all 6
sources). **Durable fix:** package-ify the kernel so workers `library()` it. Local
reproduce+fix strategy (Phase A/B/C) is in `ISSUE_sec3.4_trend_speedup.md`.

## CGLabs ops lessons (bit us repeatedly 2026-06-08…10)
- The shared node intermittently **stalls I/O** — processes stick in `D` state, terminals
  freeze, even tiny compiles/`aws --version` hang >1 h. Surfaces as `FutureInterruptError`,
  *not* a code bug. Recovery: Hub → Stop/Start My Server; escalate to ops to drain/cordon
  if a restart lands on the same node. **Pre-flight node I/O health before any long run.**
- `logs/*.log` are tracked + auto-committed then appended → every `git pull` blocks on
  "unstaged changes". `git checkout -- logs/` before pulling, else the runbook silently
  launches **old code**.
- `Data/` resolves to the climdat-source `working_dir`
  (`/home/jovyan/common_data/nex-gddp-cimp6_hazards/Data/`), not the repo.
