## 1. What was built

`data/KE-enso-explorer/provenance.json` — the §1b projection, one entry per dataset the notebook cites
(22 entries, including the exposure inputs: roads, HOT-OSM facilities, KPLC grid, WorldPop, the two
KNBS population records).

Generated by `data/KE-enso-explorer/_sources/provenance_build.py` from **your two stores, read-only**:
`metadata/cdh/*.yaml`, `metadata/cdh/draft/*.yaml`, `metadata/catalogue/*.json`, and the PR/submission
table in `metadata/cdh/README.md`. The only notebook-side input is
`_sources/provenance_keymap.json`, which carries **ids and UI routing only** — no licence, citation,
attribution or caveat text, so it cannot become a third copy.

`state` is **probed, not asserted**: the build shells out to `validate-yaml.js` from a
`cdh-metadata-standard` v0.3.0 checkout. `authored` means the record passed strict validation on this
machine. Without a checkout the build still runs, but every entry is stamped
`state_basis: "version-probe"` so a soft check can never be reported as a hard one.

Both axes render, per your correction: `state` (authored / draft / invalid / catalogue-only /
undocumented) and `hosting` (atlas / federated / unknown). §1e is enforced in code — a non-`atlas`
dataset that declared a `digital-atlas` location would have the link stripped and a gap raised.

`note` renders verbatim, in full, never collapsed, alongside `cdh.usage.not_recommended_for`.
`ensemble_season_trends.cdh.yaml` is not surfaced anywhere, as instructed.

## 2. The drift was already live — this is the evidence for §1a

The 15 hand-written dataset cards the generated catalogue replaced carried licence strings that
disagreed with the records they described:

| Dataset | Hand-written card said | CDH record says |
|---|---|---|
| Copernicus GFM | "Copernicus Open Access" | `LicenseRef-Copernicus-EMS` — **and the card omitted the required attribution string entirely** |
| JRC GloFAS | "European Commission Open Data" | `CC-BY-4.0` |
| IEBC boundaries | "Open Administrative Data" | `CC-BY-3.0-IGO` |
| KNBS NAPR / GESI | "Government of Kenya Open Data" | no record exists; the licence was invented |

Two further live defects, both now gone:

- The drawer had **no markup at all**. `openMethodDrawer()` wrote into `getElementById('drawer-title')`
  → `null`, so all ten provenance buttons threw.
- Where a key was missing from the hand-written registry the code did
  `drawerData[key] || drawerData.chirps_seasonal` — so `market_prices` and `teleconnections` silently
  showed **the CHIRPS record**. An unknown key now renders "provenance not documented" and never falls
  back to another dataset.
- WRSI is used in ~50 places in the notebook and had **no catalogue card at all**. It has an authored
  record (`eastafrica-wrsi-fews`), so generating the index from the projection added it automatically.

## 3. Ask 1 — draft records for the 8 datasets with no CDH record (priority order)

Your §5 already names these and says the cheapest useful step is writing the `note` blocks. Agreed —
that is exactly what the drawer cannot synthesise. Ordered by how much a reader can currently be
misled:

| # | Key in the projection | State now | Why it matters most |
|---|---|---|---|
| 1 | `knbs-napr` | undocumented | "Blank ≠ Zero" for NAPR is enforced in our extractor but stated **nowhere a reader sees**. Plus the season→year rule (Y = OND(Y-1) + MAM(Y)), known wrong for Tana River / Meru / Kitui / Makueni. |
| 2 | `enso-driver-indices` | undocumented | Carries three upstream indices at once. Needs RONI's "CPC revises past values", HadISST's `dmi_conc`/`dmi_pred` **NULL for all of 2025**, and Funk Western-V's non-standard definition. A z-scored distance over a NULL axis fails silently. |
| 3 | `ipc-kfssg-phases` | undocumented | IPC phases are a **classification, not a measurement**, and are not comparable across analysis rounds. Nothing on screen says so. |
| 4 | `crop-vop-intld15`, `livestock-vop` | catalogue-only | See §4 — currently rendered **unsettled**, deliberately. |
| 5 | `knbs-gesi` | undocumented | Licence needs the same KNBS scrutiny as the census/projections records (your issue #33). |
| 6 | `market-prices-fews-ndma` | undocumented | Terms-of-trade series with no stated provider terms. |
| 7 | `harveststat` | undocumented | Seasonal hole 2002–14 is a real analytical trap and is not recorded anywhere. |

Federation being approved (your §2c) means most of these can be **normal strict-passing records**
pointing at the provider, not held-back drafts. The projection already renders `hosting: federated`
correctly the moment such a record exists — no notebook change needed.

**Drop a record in either `metadata/cdh/` or `metadata/cdh/draft/` and it appears in the drawer and the
Section 6 index on the next build. No notebook edit, no key to register** (the keymap entries for all
eight already exist with `cdh: null` — set the id and it binds).

## 4. VoP is not drawered as settled

As instructed. `crop-vop-intld15` and `livestock-vop` render `state: catalogue-only`, badge **"metadata
pending"**, `settled: false`, with the catalogue's own currency-mismatch `gaps[]` text shown on the card
and in the drawer.

What the projection **cannot** show is the live gate verdict — crop PASS 1.007, livestock **FAIL 1.198**
— because `R/checks/vop_align_live_gate.R` writes its CSV to `tempdir()` and prints PASS/FAIL to stdout.
There is no durable machine-readable artifact to read.

**Small ask:** have that gate also write a stable JSON (verdict, per-population median ratio, run date,
target URL). The build already accepts one — `PROVENANCE_GATE_STATUS=<file>` merges
`{"<key>": {"name", "result", "value", "ref"}}` verbatim into `entry.gates[]`, which the drawer renders
in a never-collapsed block beside the caveats. Then a FAIL at 1.198 is visible to a reader rather than
living in a handover.
